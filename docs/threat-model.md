# Threat model summary

The service keeps consumers free of AWS credentials. API Gateway validates an
mTLS chain; the consumer Lambda additionally hashes the presented certificate's
DER bytes and strongly reads an active identity record. It authorizes using
that resolved consumer identity, never a caller-provided consumer ID.

Administrator access is normally bound to an external OIDC issuer and audience.
When a browser console origin is configured, the deployment also names one
exact OAuth scope. API Gateway enforces it on the default route and the handler
rechecks it from `scope` or `scp`; when configured it also requires the IdP app
role from `roles` or `role`, so a gateway configuration drift cannot turn
an otherwise correctly audienced browser token into an administrator token.
The unauthenticated `OPTIONS /{proxy+}` route is restricted to CORS preflight:
the handler returns before JWT processing or application audit emission.

The first enrollment creates one deployment-wide, online self-signed Hemlig
root. Its private key is AES-GCM envelope encrypted under the same application
CMK used for payload envelopes, with the distinct KMS encryption context
`service=hemlig, purpose=issuer-ca`. The admin role's `kms:Decrypt` permission
is conditioned on that context. It also has a separately conditioned payload
decrypt permission for the authenticated administrator payload-read route;
consumer roles never receive issuer-envelope access. This keeps one CMK without
treating a key alias as the sole purpose boundary.

Enrollment accepts a signed RSA CSR with a 2048-bit-or-larger public key, not a
CA certificate or private key. Hemlig issues the non-CA leaf, sets its
`clientAuth` EKU and `spiffe://hemlig/consumer/<consumerId>` URI SAN, then writes
the single root bundle at a unique S3 key. Its exact version is configured on
the custom domain, and its observed version must match before DynamoDB activates
the leaf. A leaf revocation is enforced by the strongly consistent DynamoDB
check immediately; it does not wait for API Gateway truststore propagation.
Issuer-root rotation is not exposed, avoiding an accidental lockout or
invalidation of still-valid leaves.

Payload keys are generated by KMS and payloads use AES-256-GCM with KMS and
GCM bindings to `purpose=secret-payload`, environment, immutable secret UID, and payload revision ID. Metadata
or ACL changes create a new control revision without decrypting the old
payload. Before consumer-side or administrator-side decryption, Hemlig checks
that both loaded immutable documents repeat the current head's secret ID,
environment, and exact version IDs. A copied or substituted revision fails
closed rather than turning either Lambda path into a cross-secret decrypt
oracle. Administrator plaintext reads require the authenticated admin route and
are recorded in the immutable application audit archive without plaintext.

Application audit events are emitted by this service; AWS audit services do
not infer them from `GetObject` or KMS calls. Event keys are unique and
conditionally created in an Object-Lock Compliance archive. This protects
written evidence from rewrite/deletion, but does not prove a compromised
application never wrote misleading new events. Hash-chained seals are a future
tamper-evidence enhancement.
