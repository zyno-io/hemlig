Hemlig controller has been installed.

This release watches Hemlig custom resources and Secrets cluster-wide. Its
ClusterRole is therefore intentionally broad. Review its Kubernetes RBAC as
well as each HemligProvider namespace selector and remote AgentGrant exact-secret
scope before creating HemligConsumer resources.

Install the HemligProvider, HemligConsumer, HemligSecretImport, and
HemligSecretExport resources after the administrator has minted a one-use
bootstrap capability for the consumer.

cert-manager issuer: the controller issues certificates for cert-manager
CertificateRequests that reference a HemligIssuer or HemligClusterIssuer. It
starts working once cert-manager and the crds/hemlig.zyno.io-pki.yaml CRDs are
present.

trust bundles: a HemligTrustBundle writes the anchors, intermediates and CRLs of
the CAs it lists to ConfigMaps in its namespace. It refreshes every
{{ .Values.trustBundles.refreshIntervalMilliseconds | int64 }} ms, needs the crds/hemlig.zyno.io-pki.yaml CRDs, and works
without cert-manager.
{{- if .Values.certManager.approval.grantDefaultApprover }}

ServiceAccount {{ .Values.certManager.approval.namespace }}/{{ .Values.certManager.approval.serviceAccount }} may approve CertificateRequests for the
hemligissuers.hemlig.zyno.io/* and hemligclusterissuers.hemlig.zyno.io/* signers. Every
request that references a Hemlig issuer is therefore approved, and the Hemlig
IssuanceGrant is the authorization boundary. Set
certManager.approval.grantDefaultApprover=false to hand approval to approver-policy.
{{- else }}

Default approval is off; Hemlig CertificateRequests wait for an approver.
{{- end }}

Helm does not upgrade CRDs; after an upgrade apply crds/hemlig.zyno.io.yaml and crds/hemlig.zyno.io-pki.yaml.
